Sandboxes forget. The work does not.

Agents install packages, edit a repo, and start a server. Then the box is destroyed. The next run starts from zero, context gets pasted back into the prompt, and nobody can say what changed on the machine.

  1. The disk

    Repo, virtualenv, browser profile, and data. Mounted tomorrow, not rebuilt from a script you hope is current.

  2. The processes

    Servers and jobs stay up. The agent returns to a machine that is already running, not a cold image.

  3. The record

    An append-only transcript of commands and file changes. A person can read it, replay it, or undo it.

One root. Any agent.

Brutespace is a Linux machine with a durable disk, scoped root, and an API. If an agent can speak SSH or HTTP, it can live here.

  1. 01

    Create a root

  2. 02

  3. 03

Root, with a boundary.

The agent can install and run what the work needs. You decide what it can read, write, and reach. Every command stays on the record, so a person can see what the machine became.

  • Scoped paths and network, set by you
  • Secrets kept on the machine, out of the prompt
  • Transcript you can hand to another person
  • Disk that outlives the agent session

Questions

What is a root?

A persistent Linux machine for an agent or a project. It has a real filesystem, long-lived processes, and a transcript. When the session ends, the machine stays.

Which agents can use it?

Any agent that can use SSH or HTTP, including Cursor, Claude Code, Codex, and harnesses you run yourself. Brutespace is the computer. The agent is the one typing.

Does the disk survive a restart?

Yes. The disk is the point. Packages, repos, profiles, and data are still mounted the next time the agent connects.

Who is it for?

Teams already running coding agents, and anyone building an agent that has to do real work more than once. The first version is a machine you can attach. Production permissions and audit come on that same primitive.
